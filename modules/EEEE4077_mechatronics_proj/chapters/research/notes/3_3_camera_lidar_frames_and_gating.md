> **Context**: Bridges the theoretical and geometric gap in `chapters/research/03_perception_and_tracking.md` (§3.3 Stage 2). Explains how 2D LiDAR range points and monocular camera pixels map across coordinate spaces to achieve metric obstacle tracking.

---

## 1. Physical Complementarity: The Sensor Gap

| Sensor | Superpower | Fundamental Physical Defect |
|---|---|---|
| **Monocular RGB Camera** | Rich semantic context; YOLO accurately bounds pedestrians, carts, and forklifts in image pixels. | **No metric depth (scale ambiguity)**: A 2D image cannot distinguish a human 3 m away from a cardboard cutout 0.5 m away. |
| **Planar 2D LiDAR** | Millimeter-accurate Time-of-Flight ranging ($r, \theta$) across a wide horizontal field of view. | **Semantically blind**: Collapses the 3D world into isolated, unclassified 2D laser points (e.g. two transient dots for human legs). |

**Objective:** Project the LiDAR's metric laser returns into the camera's 2D image plane to match laser ranges with YOLO-detected objects, then return the clean metric position back to the robot's ground plane.

## 2. Coordinate System Conventions

The primary source of confusion is that **Mobile Robotics** and **Computer Vision** use conflicting coordinate axis standards:

```
  ROBOT & 2D LIDAR CONVENTION (ROS / ISO 8855)           CAMERA OPTICAL CONVENTION (OpenCV)
  Ground-plane Bird's Eye View (BEV):                     Perspective Digital Image Sensor:

              ▲ Z_robot (Up / Height off floor)                    Camera Lens Center (0, 0, 0)
              │                                                      │
              │                                                      ├───► X_cam (Right across image)
              │       ▲ X_robot (Forward on floor)                   │
              │      /                                               ▼ Y_cam (Down across image)
              │     /                                               /
              └────┼────────► Y_robot (Left on floor)              ▼ Z_cam (Forward / Optical Depth!)
           Floor Plane (Z = 0)
```

### The Key Contrast:
- In the **Robot / LiDAR Frame**:
  - $X_L$: Forward distance along the floor.
  - $Y_L$: Lateral distance (left/right) along the floor.
  - $Z_L$: Vertical height. For a planar 2D LiDAR, $Z_L \approx 0$ (fixed horizontal scan plane).
- In the **Camera Optical Frame**:
  - $Z_{\text{cam}}$: **Depth** (optical distance straight out from the lens into the room).
  - $X_{\text{cam}}$: Horizontal axis (pointing to the right of the image).
  - $Y_{\text{cam}}$: Vertical axis (pointing downwards on the image sensor).

## 3. The Geometric Pipeline: From Laser to Pixels

To verify whether a laser point hits a detected pedestrian, the coordinate transformation proceeds through two physical stages:

```
[2D LiDAR Scan]  ──(1) Extrinsics [R | t]──►  [Camera 3D Space]  ──(2) Intrinsics (K)──►  [2D Image Pixels]
   (X_L, Y_L, 0)                                (X_c, Y_c, Z_c)                               (u, v)
```

### Stage A: Extrinsic Transformation ($[\mathbf{R} \mid \mathbf{t}]$)
The physical offset between the LiDAR mount (e.g. bumper level) and the camera mount (e.g. 80 cm higher on a pole):
- **Translation vector $\mathbf{t} \in \mathbb{R}^3$**: Physical displacement $(t_x, t_y, t_z)$ between sensor origins.
- **Rotation matrix $\mathbf{R} \in SO(3)$**: Angular tilt, pan, and roll alignment between sensor axes.

$$\begin{bmatrix} X_c \\ Y_c \\ Z_c \end{bmatrix} = \mathbf{R} \begin{bmatrix} X_L \\ Y_L \\ 0 \end{bmatrix} + \mathbf{t}$$

### Stage B: Intrinsic Camera Projection ($\mathbf{K}$)
The pinhole projection matrix maps 3D metric coordinates $(X_c, Y_c, Z_c)$ in front of the lens to 2D sensor pixels $(u, v)$:

$$\lambda \begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = \begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix} \begin{bmatrix} X_c \\ Y_c \\ Z_c \end{bmatrix}$$

- $f_x, f_y$: Focal lengths in pixel units.
- $c_x, c_y$: Principal point (optical center of the digital sensor).
- $\lambda = Z_c$: The projective depth factor. Expanding yields the standard pinhole equations:
  $$u = f_x \frac{X_c}{Z_c} + c_x, \qquad v = f_y \frac{Y_c}{Z_c} + c_y$$

## 4. Frustum Gating & Median Depth Filtering

### 4.1 Frustum Gating
Once all laser scan points are projected to $(u, v)$ pixel coordinates, each laser point is checked against active 2D bounding boxes $B_k = [u_{\min}, v_{\min}, u_{\max}, v_{\max}]$ generated by YOLO:

```
Camera 2D Image View:
┌───────────────────────────────────────────────────────────────┐
│                                                               │
│                     Pedestrian Bounding Box                   │
│                     [u_min = 400]        [u_max = 620]        │
│                           │                    │              │
│                           ▼                    ▼              │
│                           ┌────────────────────┐              │
│                           │      ( •  • )      │              │
│                           │         ||         │              │
│   • Laser Ray A           │   • Laser Ray B    │              │   • Laser Ray C
│   (u = 180 -> OUT)        │   (u = 510 -> IN)  │              │   (u = 840 -> OUT)
│                           │        /  \        │              │
│                           └────────────────────┘              │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

A laser ray belongs to the candidate object if its horizontal projection falls within the box columns:
$$u_{\min} \le u_j \le u_{\max}$$

### 4.2 The "Shoot-Through" Problem & Median Range Filtering
In real warehouse environments, some laser rays passing through a pedestrian's bounding box slip between their legs or past their torso and strike background walls:

```
AMR LiDAR ───► Ray 1 (hits shin) ───────────────► 2.80 m
          ───► Ray 2 (hits shin) ───────────────► 2.85 m
          ───► Ray 3 (passes between legs) ─────► [Wall behind target] ──► 18.5 m!
```

- **Arithmetic Mean Failure:** $\frac{2.80 + 2.85 + 18.5}{3} = 8.05\text{ m}$ (catastrophically corrupts distance).
- **Median Filter Solution:** Sorting $[2.80, 2.85, 18.5]$ yields the median **$2.85\text{ m}$**, robustly rejecting background outliers.

## 5. Returning to Bird's Eye View (BEV)

Once the obstacle's true metric range $r^*$ and bearing angle $\theta^*$ are extracted:
1. The measurement is transformed back into the 2D robot floor frame:
   $$x_m = r^* \cos(\theta^*), \quad y_m = r^* \sin(\theta^*)$$
2. Because wheeled AMRs operate exclusively on flat 2D floors ($Z = 0$), vertical height is discarded.
3. The clean measurement $\mathbf{z} = [x_m, y_m]^T$ is passed directly to the **Stage 3 Kalman Filter** for dynamic velocity estimation.
